# Linux Wwise Vorbis conversion and quick-menu probe

## Result

One private 1.5-second, 48 kHz stereo FSD recording was converted to a Wwise Vorbis WEM on SteamOS. The custom WEM has RIFF tag 0xFFFF, a 66-byte fmt chunk, a 16-byte hash chunk, and a data chunk. It is 2-channel, 48 kHz, and 72,000 PCM frames (1.5 seconds).

The file matches the outer layout of the private native NMS quick-menu reference. vgmstream identifies it as Custom Vorbis and decodes it to a 1.5-second, 48 kHz stereo WAV. The NMS game has not yet been used to play this custom file, so runtime compatibility remains unconfirmed.

The WEM's subtype/channel value (0x00000000) and codebook UID (0x20CEF588) differ from the native reference (0x00003102 and 0xEC69CB18). Their meaning and runtime effect are not established. The diagnostic uses the converter's values without manually patching unknown fields.

## Linux tool assessment

| Tool | Local finding | Decision |
| --- | --- | --- |
| FFmpeg 8.1.2 / FFprobe | Available; FFmpeg includes libvorbis. | Encode the source WAV to temporary Ogg Vorbis at 48 kHz, stereo, quality 6. |
| [wav2wem](https://github.com/pas2k/wav2wem) | Go source at commit 38e916953bec63862b13b449d780d1303a1bf29c; Go tests pass. GPL-2.0. Its direct WAV path launches an embedded Windows oggenc2.exe, which fails on this Linux host. | Use its Ogg-input WEM repacketizer after FFmpeg. Do not feed it WAV on Linux. |
| [wem-audio](https://github.com/LambdaEd1th/wem-audio) | Pure Rust library, AGPL-3.0-or-later; no CLI. Its writer emits a 24-byte fmt chunk and a separate vorb chunk, unlike the current NMS reference layout. Rust and Cargo were absent. | Not selected for this NMS probe; its output would need separate runtime validation. |
| [sound2wem](https://github.com/EternalLeo/sound2wem) | Wwise Console workflow with Vorbis Quality High; its helper script is Windows CMD-based. | Keep as the known Wwise Console route where Windows Authoring/Console is available. |
| [vgmstream](https://github.com/vgmstream/vgmstream) | CLI was absent from PATH; a temporary upstream Linux CLI was used for offline decode verification. | Optional but recommended in the reproduction command below. |
| Wine | Absent from PATH. | Not used. |

The Go compiler used for the offline build check was downloaded to a temporary directory from the official Go distribution and verified against its published SHA-256. No system-wide tool installation was made.

## Rebuild the one-file probe

Install Go and build the pinned helper:

~~~sh
go install github.com/pas2k/wav2wem/cmd/wav2wem@38e916953bec63862b13b449d780d1303a1bf29c
~~~

Then run from the repository root with the private source and a locally extracted known-good native reference WEM:

~~~sh
python3 tools/build_quickmenu_probe.py \
  --source-wav private/audio_sources/clip_001.50s_e66530bbbade.wav \
  --output-zip "$HOME/Downloads/NMS_FSD_QuickMenu_WwiseVorbis_Diagnostic.zip" \
  --wav2wem "$(go env GOPATH)/bin/wav2wem" \
  --vgmstream-cli /path/to/vgmstream-cli \
  --reference-wem /path/to/private/native-quickmenu-reference.wem
~~~

The vgmstream and reference options are optional. The builder checks the WAV and temporary Ogg metadata, creates the WEM through the Ogg-input path, validates RIFF chunks and the 48 kHz stereo frame count, and writes a ZIP with four copies under MODS-root/AUDIO/WINDOWS/MEDIA. The ZIP includes a readme and a manifest and refuses to overwrite an existing output file. It contains no BNK.

The pinned wav2wem source documents output as aoTuV-6.03 Wwise Vorbis with modified packets and a seek table, and reports decoding against vgmstream/ww2ogg. The local 1.5-second output was independently recognized and decoded by vgmstream. This does not replace the Steam Deck in-game playback gate.

## Offline tests

Run the synthetic RIFF parser and ZIP layout tests with:

~~~sh
python3 -m unittest discover -s tests -v
~~~

These tests use generated byte fixtures and contain no private audio or game extracts. The local diagnostic build additionally validated the actual private source, generated WEM, reference structure, and vgmstream decode.

## Steam Deck test

1. Exit No Man's Sky.
2. Temporarily disable or move the earlier FSD, PCM16 custom-WEM, and quick-menu probe folders outside GAMEDATA/MODS. Keep those folders for rollback.
3. Extract the diagnostic ZIP into GAMEDATA/MODS. The ZIP contains one package folder with AUDIO directly under that root.
4. Launch the game and open the quick menu repeatedly. Report whether the custom FSD cue plays, the menu is silent, or vanilla audio remains.
5. Exit, move only this diagnostic folder out of MODS, relaunch, and check that vanilla quick-menu audio returns.

Do not install other FSD builds alongside this probe. Do not modify a persistent BNK. No files have been written to the installed game or existing mod folders during preparation.
